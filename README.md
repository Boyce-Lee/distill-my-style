# distill-my-style

把协作中明确表达的做事习惯，提炼成 agent 能在日常协作中自动采用的个人风格 Skill。

你决定什么时候沉淀，agent 回看当前对话、提出候选和修改方案。你确认后，它才创建或更新个人风格。后续 session 使用已确认的偏好，减少重复提醒和纠正。

## 两种 Skill，两种职责

| | `distill-my-style` | `<个人标识>-style` |
| --- | --- | --- |
| 内容 | 提炼、确认、创建、更新和校验流程 | 已确认的个人做法与取舍偏好 |
| 启动 | 用户显式调用 | 日常协作中隐式选择，按条件应用相关偏好 |
| 更新 | 提出方案，用户确认后写入 | 作为成果被更新，不包含自我更新流程 |

“沉淀风格”启动一次复盘，不会让日常工作变成持续收集偏好的过程。一次纠正会先在当前任务中落实；是否成为长期习惯，由你在沉淀时确认。讨论触发词、引用示例或修改这个工具本身，不会启动个人风格提炼。

## 快速开始

### 安装

推荐通过 [Skills CLI](https://github.com/vercel-labs/skills) 安装，需要 Node.js 22.20+ 和 npm：

```sh
npx skills add Boyce-Lee/distill-my-style -g
```

`-g` 安装到用户级目录，适合跨项目、跨 session 使用；省略它则安装到当前项目。按安装提示选择所用工具，也可以明确指定：

```sh
npx skills add Boyce-Lee/distill-my-style -g -a codex claude-code trae
```

### 发起一次沉淀

在完成一段工作、明确了一些偏好后，显式调用：

```text
$distill-my-style 沉淀风格，回看当前对话，先给我候选和依据。
```

Claude Code 使用 `/distill-my-style` 发起同样的请求；Trae 中明确要求使用 `distill-my-style`。首次使用时，agent 会提出目标名称和保存位置；已有绑定时，它会先读取现有风格，再提出增量修改。

确认方案可以是“全部确认”，也可以逐条处理：

```text
确认第 1 条。第 2 条只适用于技术讲解，不扩大到所有回答；请改写后再给我看。
第 3 条只是这次项目的要求，不记录。
```

明确批准的部分才写入；仍有歧义的部分继续确认。没有足够依据时，不创建空的个人风格。

### 准备脚本运行环境

首次执行前，准备 Python 3.8+，并在已安装的 `distill-my-style` 目录中安装校验器依赖：

```sh
python -m pip install -r requirements.txt
```

使用可用的 Python 3.8+ 解释器；本机命令为 `python3` 时，将上面的 `python` 替换为 `python3`。

Skills CLI 安装 Skill 文件，不自动安装 Python 依赖。`target.py` 只使用 Python 标准库；`validate_style.py` 使用 PyYAML 解析 YAML。执行脚本时使用已安装依赖的同一 Python 环境。

### 手动安装（备用）

也可以将本仓库的完整内容放入所用工具支持的 Skill 目录，保留 `SKILL.md`、`agents/`、`scripts/` 和 `requirements.txt` 等配套文件：

| 工具 | 个人 Skill 目录 |
| --- | --- |
| Codex | `~/.agents/skills/distill-my-style/` |
| Claude Code | `~/.claude/skills/distill-my-style/` |
| Trae | `~/.trae/skills/distill-my-style/` |

手动安装同样需要准备上述 Python 环境与依赖。

## 一次完整的工作流程

1. **读取目标**：调用固定脚本读取绑定，再读取对应的风格正文。
2. **回看材料**：从当前 session 可见的用户要求、纠正和选择理由中提炼候选。
3. **提交方案**：展示表达依据、具体规则、适用范围，以及拟新增、修改、合并或删除的内容。
4. **等待确认**：用户决定哪些内容成为长期偏好；确认前不写回个人风格或绑定。
5. **创建或融合更新**：按 `SKILL.md` 中的格式与成果要求直接撰写，更新保留有效内容和适当结构。
6. **校验与审阅**：脚本检查客观错误，agent 按成果标准检查语义质量。
7. **保存绑定与交付**：完成已确认的绑定操作，给出实际文件位置和变更说明。

执行细则见 [SKILL.md](SKILL.md)。上下文缺失时，只使用实际可见的材料；项目规范、工具限制和 agent 自己的建议不能直接算作个人风格。

关键设计取舍与演进见 [CHANGELOG.md](CHANGELOG.md)。

## 个人风格应保持什么质量

成果需要可识别、允许隐式调用、有个人辨识度、可执行、有适用边界、自包含、职责纯粹，并且精炼一致。`xxx-style` 的 `xxx` 代表一个人：description 应说明这是贯穿日常协作的个人做事风格，正文再说明各条偏好的具体做法与条件。整体入口不限定为某个任务，局部偏好也不扩大到所有任务。

一个示意片段如下；具体偏好必须来自使用者的确认：

```markdown
---
name: sample-style
description: >-
  在日常协作中自动应用此人的已确认做事风格，具体偏好按各自适用条件执行。
  技术讲解偏好先给最小例子，再解释机制。
---

- 解释复杂机制时，先给最小具体例子，再展开对象关系与执行链路。
  用户明确要求简答时，按当次要求处理。
```

### 规范与灵活性

- **固定的部分**：入口格式、合法名称、有效 description、隐式调用策略，以及内容必须经过确认。
- **推荐的组织**：行为规则优先用列表；多个独立主题用简短、准确的标题分组，同一主题的少量规则直接列出。全局适用边界独立放在正文开头或结尾。
- **压缩的边界**：每条保留完整偏好，相关做法、条件和例外放在一起。去掉重复措辞，保留个人取舍和具体动作，不缩成空泛标签，也不逐句拆碎。
- **灵活的部分**：栏目、层级、条目数量、顺序和句式随内容决定。只有一条简短偏好时可以用段落，不为填满结构补造内容。
- **更新方式**：融合原有结构，必要时提出重组，不为统一版式重写全文，不机械追加“本轮新增”。

格式和成果要求直接定义在 [SKILL.md](SKILL.md) 中，无需独立模板。没有例外时不补造例外，一句话能讲清的规则不拆成固定字段。

### 两层检查

| 检查 | 负责什么 |
| --- | --- |
| 固定脚本 | 文件名、YAML、名称与目录、description 类型和长度、本地引用、包内隐式调用开关 |
| 内容审阅 | 用户确认一致性、个人辨识度、具体做法与范围、任务匹配、组织清晰度、压缩是否保留含义、自包含、重复与冲突 |

校验器不按关键词、章节数量或句式给风格打分。格式通过后仍需内容审阅；涉及已确认含义、范围或调用策略的修正，需要重新确认受影响部分。

## 跨 session 的目标绑定

使用者自己的绑定固定存放在：

```text
~/.distill-my-style/target.json
```

它只有两个字段：个人风格 Skill 的名称，以及实际 `SKILL.md` 的绝对路径。默认推荐成果位置为 `~/.agents/skills/<个人标识>-style/SKILL.md`，已有位置约定或绑定优先。

绑定由 [scripts/target.py](scripts/target.py) 维护。它帮助下一个 session 定位修改目标；日常应用个人风格时无需读取绑定。绑定属于本机用户状态，分发工具或风格成果时不包含它。

| 命令 | 行为 |
| --- | --- |
| `read` | 只读，不创建目录；区分未绑定、有效绑定和错误 |
| `create` | 目标已经存在且名称符合时首次绑定；已有记录禁止覆盖 |
| `update` | 提供最近读取的旧名称和路径；旧值变化则拒绝写入 |

脚本采用排他锁和同目录临时文件原子替换，避免并发覆盖与半写入记录。目标缺失、记录损坏、权限错误或锁被占用时返回错误，不当作首次创建，也不自动覆盖重建。

个人风格文件和绑定是两次操作：绑定失败时保留并报告风格文件的实际保存结果。锁保护绑定记录，不保护两个 session 对风格正文的同时编辑；写回前还需检查正文是否变化。

## 显式与隐式调用配置

本工具的显式策略保存在包内：

- Claude Code：`SKILL.md` frontmatter 中的 `disable-model-invocation: true`。
- Codex：`agents/openai.yaml` 中的 `policy.allow_implicit_invocation: false`。
- Trae：执行流程要求用户明确调用，尚未确认有同等的平台强制开关。

产出的个人风格使用隐式策略，不继承上述限制。被所用工具发现后，agent 可按 description 在适用任务中选择它。

Claude 的显式开关是平台扩展字段，严格的通用打包器可能拒绝它。当前包保留该字段以支持 Claude Code 的手动调用；平台的真实加载与匹配效果仍需在目标版本中验证。

## 验证与维护

以下命令从 Skill 目录运行，并使用已安装依赖的 Python 环境。

```sh
python -m unittest discover -s tests -v
python scripts/target.py --help
python scripts/validate_style.py --help
```

测试使用临时目录，不读取或修改你的真实绑定。校验实际个人风格时，将目标目录作为一个参数传入：

```sh
python scripts/validate_style.py "/absolute/path/sample-style"
```

通过时退出码为 `0`，输出 `{"status": "valid", "errors": []}`。未通过时退出码为 `1` 并列出错误。校验器只读，不会修改成果。绑定脚本同样返回 JSON；不要绕过脚本直接编辑记录。

## 包内文件

```text
distill-my-style/
├── SKILL.md                     # agent 执行指令
├── README.md                    # 使用与设计说明
├── CHANGELOG.md                 # 关键设计取舍与演进
├── skill.json                   # 管理元数据
├── requirements.txt             # 校验器依赖
├── agents/openai.yaml           # Codex 显式调用策略
├── scripts/
│   ├── target.py                # 绑定读写
│   └── validate_style.py        # 成果客观校验
└── tests/                       # 临时目录中的脚本测试
```

本包不需要原作者的聊天记录、私人路径或外部仓库。保存成功、被工具发现和实际遵循是不同的验证结果；格式检查不能证明模型始终遵循偏好，用户确认也不是由脚本自动证明的。
